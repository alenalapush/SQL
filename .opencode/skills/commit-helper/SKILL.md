# Commit Helper

Формирует git-коммиты по стандарту [Conventional Commits v1.0.0](https://www.conventionalcommits.org/en/v1.0.0/) на русском языке.

## Формат коммита (шаблон)

```
<тип>(<область>): <описание>

<тело>

<подвал>
```

### Обязательный шаблон для единообразия

Копируй этот шаблон при создании каждого коммита:

```
тип(область): описание

Что изменилось и почему (строка до 72 символов, 
при необходимости с переносом на новую строку)

Подвал (опционально)
BREAKING CHANGE: описание
Closes #123
Co-authored-by: Имя <email>
```

**Правила заполнения шаблона:**
- `тип` — строго один из 11 типов ниже, всегда в нижнем регистре
- `область` — опционально, в скобках, нижний регистр, без пробелов
- `!` — ставится перед `:` при breaking change: `feat!:`, `fix(scope)!:`
- `описание` — обязательно, повелительное наклонение, до 72 символов, без точки в конце
- `тело` — отделяется пустой строкой, строки до 72 символов, отвечает на "что?" и "почему?"
- `подвал` — отделяется пустой строкой от тела

## Типы коммитов и их влияние на SemVer

| Тип | Описание | SemVer |
|-----|----------|--------|
| `feat` | Новая функциональность | MINOR |
| `fix` | Исправление ошибки | PATCH |
| `docs` | Изменения в документации | — |
| `style` | Форматирование (отступы, точки с запятой, пробелы) | — |
| `refactor` | Рефакторинг без изменения поведения | — |
| `perf` | Улучшение производительности | PATCH |
| `test` | Добавление или исправление тестов | — |
| `build` | Изменения в системе сборки или зависимостях | — |
| `ci` | Изменения в CI/CD конфигурации | — |
| `chore` | Рутинные задачи (инструментарий, .gitignore, обслуживание) | — |
| `revert` | Откат предыдущего коммита | PATCH |

**Breaking change** (любой тип + `!` или `BREAKING CHANGE:` в подвале) → **MAJOR**

## 7 правил хорошего коммита

1. **Выбери правильный тип** — критически для SemVer и автогенерации changelog'ов
2. **Добавь область (scope), когда это важно** — модуль/компонент/слой, нижний регистр
3. **Пиши описание в повелительном наклонении** — "добавить", "исправить", "обновить" (не "добавил", "исправил")
4. **Отделяй заголовок от тела пустой строкой** — иначе парсеры не различают секции
5. **Заголовок до 72 символов** — не влазит → разбей коммит или унеси детали в тело
6. **В теле объясняй что и почему, а не как** — код и так показывает "как"
7. **Используй подвал для метаданных** — BREAKING CHANGE, Closes, Co-authored-by

## Область (scope)

Область уточняет, какой компонент затронут. Опциональна, но рекомендуется на больших проектах.

**Правила:**
- Нижний регистр, без пробелов
- Существительное: `api`, `auth`, `db`, `ui`, `deps`
- Один коммит — одна логическая область
- Если изменение затрагивает несколько областей — подумай о разделении коммита
- Если область неочевидна — опусти её

Примеры:
```
feat(api): добавить эндпоинт регистрации
fix(auth): исправить ошибку 401 при истёкшем токене
chore(deps): обновить axios с 1.6.0 до 1.7.0
docs(readme): добавить раздел с переменными окружения
```

## Breaking changes

Два способа указать на breaking change:

**Способ 1 — `!` после типа/области:**
```
feat!: изменить формат ответа API
feat(auth)!: удалить поддержку session-токенов
```

**Способ 2 — `BREAKING CHANGE:` в подвале (подробный):**
```
feat: перейти на JWT-аутентификацию

BREAKING CHANGE: эндпоинт /api/auth теперь возвращает JWT-токен вместо session-cookie.
Клиенты, использующие session-аутентификацию, должны мигрировать на токены.
```

## Подвал (footer)

Используется для метаданных в формате git trailers:

```
BREAKING CHANGE: описание несовместимых изменений
Closes #123, #456
Closes JIRA-789
Co-authored-by: Имя Фамилия <email>
Reviewed-by: Имя Фамилия <email>
Refs #321
```

Правила:
- Отделяется пустой строкой от тела
- Токен и значение разделяются `: ` или ` #`
- `BREAKING CHANGE` — исключение (может содержать пробел)
- Остальные токены через дефис: `Co-authored-by`, `Acked-by`

## Антипаттерны (чего делать НЕ надо)

| Плохо | Почему |
|-------|--------|
| `update file` | Не говорит что и зачем |
| `fix bug` | Какой баг? Где? |
| `WIP` | Бесполезно в истории |
| `asdf` или `123` | Мусор |
| `правки` | Непонятно что и где |
| `feat: много изменений в auth и api и ui` | Слишком широко, надо разбить |
| `Исправил баг` | Прошедшее время, нарушение правила #3 |
| `update user.py` | Описывает файл, а не изменение |

## Примеры правильных коммитов

### Новая функциональность
```
feat: добавить тёмную тему на страницу настроек

Пользователи теперь могут переключать тему оформления в личном кабинете.
Тема сохраняется в localStorage.
```

### Исправление ошибки
```
fix(api): возвращать 400 вместо 500 при пустом email

Валидация теперь происходит до вызова сервиса, а не в нём.
```

### Рефакторинг
```
refactor(auth): вынести проверку JWT в middleware

Упрощает контроллеры и централизует логику аутентификации.
```

### Документация
```
docs(readme): добавить инструкцию по установке и настройке
```

### Зависимости
```
chore(deps): обновить React с 18.2 до 18.3
```

### Тесты
```
test(auth): добавить тесты на вход с невалидным паролем
```

### CI/CD
```
ci: добавить CodeQL-сканирование в PR-воркфлоу
```

### Breaking change
```
feat(api)!: переименовать эндпоинт /users в /accounts

BREAKING CHANGE: старый эндпоинт /users удалён. Все клиенты должны
использовать /accounts.
```

## Алгоритм работы при формировании коммита

1. **Проверить изменения**: `git status` и `git diff`
2. **Проанализировать что изменилось** — определить тип и область
3. **Выбрать подходящий тип** из таблицы (feat/fix/refactor/docs/chore — 90% случаев)
4. **Определить область (scope)**, если изменение локально
5. **Написать сообщение по шаблону** — повелительное наклонение, ≤72 символов
6. **Проверить соответствие правилам** — тип, регистр, длина, точка, пустые строки
7. **Создать коммит**: `git add` и `git commit`

## Шпаргалка (быстрый старт)

```
feat: добавить расчёт скидки для постоянных клиентов
fix(api): исправить ошибку 500 при пустом теле запроса
refactor: вынести валидацию email в отдельный сервис
docs(readme): обновить инструкцию по установке
feat!: изменить формат ответа API
test(auth): добавить тесты на логин с невалидным паролем
chore(deps): обновить express с 4.18 до 4.19
style: отформатировать код по Prettier
perf(db): добавить индекс на users.email
ci: добавить проверку commitlint в CI
revert: откатить "feat: добавить тёмную тему"
```
