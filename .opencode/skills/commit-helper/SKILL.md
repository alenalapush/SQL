## Что делает

- Формирует git-коммиты по стандарту Conventional Commits на русском языке
- Проверяет и исправляет существующие сообщения коммитов
- Объясняет правила написания коммитов

## Формат коммита

```
<тип>(<область>): <описание>

<тело>

<подвал>
```

## Типы коммитов

| Тип | Описание |
|-----|----------|
| `feat` | Новая функциональность |
| `fix` | Исправление ошибки |
| `docs` | Изменения в документации |
| `style` | Форматирование кода (отступы, точки с запятой и т.п.) |
| `refactor` | Рефакторинг кода без изменения поведения |
| `perf` | Изменения для улучшения производительности |
| `test` | Добавление или исправление тестов |
| `build` | Изменения в системе сборки или зависимостях |
| `ci` | Изменения в CI/CD конфигурации |
| `chore` | Рутинные задачи (изменения в .gitignore и т.п.) |
| `revert` | Откат предыдущего коммита |

## Правила написания

1. Описание коммита — в повелительном наклонении, настоящем времени: "добавить", "исправить", "обновить" (не "добавил", "исправил")
2. Максимум 72 символа в заголовке
3. Без точки в конце заголовка
4. Тело отделяется пустой строкой, строки до 72 символов
5. В теле отвечать на вопросы "что?" и "почему?", а не "как?"
6. Breaking changes: добавить `!` после типа или `BREAKING CHANGE:` в подвале
7. Один коммит — одно логическое изменение
8. Если изменения затрагивают несколько типов — разбить на несколько коммитов

## Алгоритм работы при формировании коммита

1. Проверить изменения: `git status` и `git diff`
2. Проанализировать что изменилось
3. Выбрать подходящий тип коммита
4. Определить область (scope), если уместно
5. Написать корректное сообщение
6. Создать коммит через `git add` и `git commit` или предложить пользователю команду для копирования

## Шпаргалка (быстрый старт)

```
feat: добавить расчёт скидки для постоянных клиентов

fix(api): исправить ошибку 500 при пустом теле запроса

refactor: вынести валидацию email в отдельный сервис

docs(readme): обновить инструкцию по установке

feat!: изменить формат ответа API (BREAKING CHANGE)

test(auth): добавить тесты на логин с невалидным паролем
```
